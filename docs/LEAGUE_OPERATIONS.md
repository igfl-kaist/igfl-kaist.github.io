## 2026-10-19 최신 결정: 선수·팀 모집 시범 개통

사용자는 현재 정보 자동 정리·새 시트 검증 전환과 이전 파일/사본/휴지통의 운영자 수동 파기, 삭제 자료 복구 요청·복원 사용 금지 원칙으로 시범 운영을 시작하기로 했다. 선수 가입·팀 신청만 개통하고 경기 등록(`LEAGUE_SEASON_OPEN`)·리그 메일 자동 발송(`LEAGUE_EMAILS_ENABLED`)은 계속 닫는다. 인증은 24시간 전체 예약 300회, 이메일별 시간당 5회·60초 간격·코드 5분·세션 12시간을 유지한다. Google 실제 잔여 수신자 한도도 계속 강제한다.

기준일: 2026-10-19. 현재 공개 홈페이지는 https://igfl-kaist.github.io/ 이며 저장소는 igfl-kaist/igfl-kaist.github.io 다. 확정된 정상 경기·팀 운영 흐름을 구현했다. 실제 선수 가입과 시즌을 개통한 상태는 아니다. Google 처리 고지·변경 이력 파기·주기적 정리 검증과 사용자 개통 지시 전에는 합성 데이터만 사용한다.

## 코드와 저장 구조

- `server/league.mjs`: 환경 독립적인 리그 명령·권한·상태 전이·조회·집계. 잘못된 명령은 원본 상태를 변경하지 않는다.
- `server/images.mjs`: 이미지 MIME·실제 파일 서명·크기·해상도 검증.
- `apps-script/LeagueAdapter.gs`: 기존 인증 서버 세션·ScriptLock·비공개 Sheets와 연결한다.
- `src/league-ui.mjs`, `src/league.css`: 실제 서버 데이터로 렌더링하는 화면과 역할별 조작. 30초 주기 및 온라인/탭 복귀 시 갱신한다. 서버 push 방식은 아니다. 입력 중에는 폼을 덮어쓰지 않고 변경 안내를 표시한다.
- `dev/`, `scripts/dev.mjs`: 같은 엔진을 실행하는 localhost 합성 검증 서버. 임의 계정 선택은 이 환경에서만 가능하며 정적 빌드에 포함되지 않는다. 서버 직렬 큐와 임시 파일 rename으로 저장한다.

현재 파일럿은 공개 선수 목록과 비공개 프로필을 서로 다른 배열에 두고, API에서 허용한 필드만 투영한다. 동일한 소유자 전용 시트에 저장하지만 일반 이용자에게 시트를 공유하지 않는다. 공개 클라이언트가 개인정보를 내려받아 숨기는 방식이 아니다. 세션 토큰 원문은 저장소·시트에 넣지 않는다.

### 리그 저장소 초기화와 버전 갱신

1. 기존 인증 프로젝트·인증 시트를 유지한다. `initializeAuth()`를 다시 실행하지 않는다.
2. `node scripts/build-gas.mjs`로 만든 `.local/AppsScript.gs`를 편집기 `Code.gs`에 저장한다. 기존 `appsscript.json`의 두 OAuth 범위는 그대로다.
3. 소유자가 `initializeLeagueStorage()`를 한 번 실행한다. `LeagueSnapshots` 탭과 최초 상태만 추가한다. 이미 있으면 유지한다. 웹 API에서는 이 함수를 호출할 수 없다.
4. 기존 웹 앱 배포를 새 버전으로 갱신한다. 소유자 실행·모든 사용자 호출 설정, `/exec` 주소는 유지한다.
5. 초기 상태는 선수/팀 0, 가입 닫힘, 시즌 준비다. 합성 샘플을 실제 서버에 넣지 않는다.

`LeagueSnapshots`에는 JSON 전체 상태를 UTF-8 base64로 인코딩하고 `IGFL:` 접두사를 붙여 32,000자 단위로 저장한다. 텍스트 형식과 접두사는 시트 수식 실행을 막고 한글·이모지 분할 손상을 피한다. 모든 조각 기록·flush 후 `LEAGUE_ACTIVE_SNAPSHOT` 속성 하나를 바꾸는 지점에서 커밋한다. 중간 실패는 기존 스냅샷을 유지한다. 명령과 첫 심판 수락·경기 최종 확정은 같은 ScriptLock 안에서 실행한다.

**용량·운영 한계:** 상태 원문 4,000,000자에서 저장을 거부하며 과거 스냅샷은 개인정보 정리와 회원 탈퇴 완료 단계에서 최신 상태 확정 후 비운다. Google 자체 변경 이력 파기는 별도 검증이 필요하다. 이미지도 상태 안에 있으므로 팀 수·이미지 변경·경기·감사 이력이 늘면 시트가 빠르게 커진다. 현재는 적은 인원의 파일럿 어댑터다. 실제 모집 전 예상 인원·요청량·메일 할당량을 점검하고, 장기 운영은 DB와 객체 이미지 저장소 분리를 검토한다. Apps Script/Sheets의 무료 한도가 항상 충분하다고 보장하지 않는다.

### 운영 설정

모두 Apps Script의 **Script Properties**에 넣는다. 실제 값은 저장소에 기록하지 않는다.

| 속성 | 기본값과 용도 |
| --- | --- |
| `LEAGUE_REGISTRATION_OPEN` | 기본 false. 별도 저장소 검토 승인과 사용자 개통 지시가 모두 필요 |
| `PRIVACY_STORAGE_APPROVED` | 기본 false. 현재 Sheets의 변경 이력 파기 미충족으로 승인하지 않음. 이 값과 가입 스위치가 모두 true여야 등록 허용 |
| `PRIVACY_MAINTENANCE_STATUS` | 자동 정리 실행/실패·마지막 성공 시각·건수. 비밀값·개인 식별 정보 제외 |
| `PRIVACY_PROBE` | 소유자 합성 시험용 파일과 격리된 속성·11개 검증 결과. 운영 백업으로 사용하지 않음 |
| `PRIVACY_VERSION` / `PRIVACY_NOTICE` | 기본 빈 값. 최종 수집·이용 동의 버전과 안내 본문. 가입 열림 외에 이 두 값도 있어야 서버가 등록 허용 |
| `LEAGUE_SEASON_ID` / `LEAGUE_SEASON_NAME` | 기본 pilot / 시즌 준비. 시즌 ID는 경기 기록 귀속 키이므로 임의 교체 금지 |
| `LEAGUE_PHASE` | 기본 regular. 프리시즌은 preseason, 시즌 ID도 별도 사용 |
| `LEAGUE_SEASON_OPEN` | 기본 false. 시즌 운영 합의 후 true로 일정 등록 허용 |
| `TEAM_GRACE_DAYS` | 기본 60. 인원 미달 유예의 기술 기본값. 운영 결정 시 양의 정수로 조정 |
| `LEAGUE_ADMIN_USER_IDS` | 운영진 내부 사용자 ID를 쉼표로 구분. 브라우저에서 제출한 admin 값을 사용하지 않음 |
| `LEAGUE_ADMIN_EMAILS` | 운영진 알림 수신 주소. 관리자 권한 부여와 별개 |
| `LEAGUE_SITE_URL` | 실제 이용자가 접속할 홈페이지 URL. 알림의 링크에 사용 |
| `LEAGUE_EMAILS_ENABLED` | 기본 false. 수신자·홈페이지·트리거 준비 후 true |

최초 운영진은 실제 이메일 인증 후 소유자 `inspectOperationsSetup()`으로 계정 매핑 준비 상태를 확인하고 `configureOperationsAdmin()`으로 지정한다. 공개 운영 문의 주소에 해당하는 고유 Accounts 매핑의 내부 ID만 권한에 추가한다. 중복·충돌·탈퇴 정리 중 계정은 거부하고 기존 운영진 ID는 보존한다. 이메일을 내부 ID 대신 넣으면 권한이 생기지 않는다. 운영진 자신은 선수 미등록이어도 운영 관리가 가능하다. 사용자에게 관리자 선택 항목을 제공하지 않는다.

2026-10-16 사용자 승인으로 `AUTH_EMAIL_SCOPE=kaist`를 적용해 정확한 `@kaist.ac.kr` 인증을 허용했다. 하위 도메인·유사 도메인은 계속 거부한다. 소유자 도구 `allowKaistEmailAuthentication()`은 선수 가입이 닫혀 있을 때만 이 범위를 변경하며 가입·시즌을 열지 않는다. `pilot`으로 제한하면 `PILOT_EMAILS` 목록을 다시 강제한다. 이메일은 정규화하고 학번/사번은 앞뒤 공백 제거 후 중복 거부한다. 별칭 병합·식별번호 변경은 자동 처리하지 않는다.

유예 만료 정리는 API 요청과 시간 기반 개인정보 정리 작업에서 실행한다. 별도의 마감 통보 메일은 개통하지 않았다.

### 메일 작업과 장애 대응

심판 후보마다 별도 작업을 기록하며, 팀 신청·자격 확인·이의·불일치·외부 경기 승인 대기는 운영진 작업으로 기록한다. 경기 수락·결과 확인은 홈페이지 안에서만 진행한다. 메일에 선수의 비공개 프로필이나 전체 경기 기록을 넣지 않는다.

실제 메일 개통을 별도로 승인한 뒤에만 `LEAGUE_EMAILS_ENABLED=true`와 `processLeagueEmails()` 시간 기반 트리거를 설정한다(예: 1분 간격). 실행당 최대 10건, 작업당 시도 상한 3회. 잔여 MailApp 할당량·수신자가 없으면 작업을 pending으로 유지한다. 잠금 안에서 sending으로 선점하고 메일 발송은 잠금 밖에서 수행한다. 성공은 sent, 발송 예외는 uncertain이다. 중간 실행 종료로 남은 sending도 확인 대상이다.

MailApp에는 멱등 발송 키가 없어서 예외/시간 초과가 실제 미수신을 뜻하지 않는다. **uncertain/sending은 자동 재발송하지 않는다.** 운영진이 발송함과 알림 ID를 확인한 뒤 소유자 도구로 작업을 복구해야 한다. 현재 웹 관리 화면은 상태 확인만 제공한다. 시트 조각을 직접 편집하지 말고 잠금·새 스냅샷 절차로 복구한다. 자동 메일 트리거는 아직 설치하지 않았다. 2026-10-19 소유자 전용 도구의 제한된 수동 발송 시험 결과는 [배포 기록](AUTH_DEPLOYMENT.md)을 따른다.

### 백업과 복구

현재 평문 개인정보를 포함한 전체 인증 시트·Script Properties 사본의 생성·운영 복원은 개통 전 보류한다. 변경 이력에서 회원별 파기를 할 수 없는 Google Sheets 구조를 그대로 백업하면 탈퇴 전 정보를 되살릴 수 있다. 현재 셀을 정리해도 기존 사본은 갱신되지 않는다. 소유자 합성 사본으로 이를 검증하며 운영 파일은 임의 삭제하지 않는다.

부분 쓰기의 기존 포인터 보호는 유지한다. 과거 포인터로의 수동 롤백이나 원시 시트 전체 복원은 회원 탈퇴·세션 폐기를 되돌릴 수 있어 지원하는 복구 절차로 안내하지 않는다. 백업 외부 삭제 원장·인증 전면 폐기·권한과 기록 재검증을 구현하고, 실제 파기 가능한 저장 구조를 정한 뒤 복구를 검증해야 한다. [개인정보 삭제 검증](PRIVACY_VERIFICATION.md)을 따른다.

## 이미지·보안·충돌 처리

브라우저는 JPG/PNG/WebP 입력 최대 3MB를 받아 긴 변 512px JPEG로 최적화하고 메타데이터를 제거한다. 서버는 data URL·base64·실제 이미지 서명·최대 1024px·디코딩 150KB를 다시 검사한다. SVG는 받지 않는다. 팀 관리에서 기본 이미지로 복원 가능하다.

모든 명령은 서버에서 역할·대상·선수 자격·정원·심판 중립성을 검증한다. 전역 revision과 경기 버전이 달라지면 쓰기를 거부하고 최신 기록을 다시 불러오도록 안내한다. 기록 수정은 양 팀의 기존 확인을 해제한다. 불일치/이의 검토 중에는 최종 승인이 불가능하다. 확정 경기는 중복 요청해도 Elo를 다시 반영하지 않는다.

최신 사용자 결정에 따라 취소·중단·행정 몰수·재경기·확정 후 정정과 출전 정지를 구현했다. 중단·몰수는 정상 확정과 Elo에서 제외한다. 정정은 사유·새 버전·양 팀 재확인·최종 승인을 거치며, 최종 승인 전에는 기존 공식 결과를 유지한다. 시즌 이월·컵 세칙은 미정이다.

## 2026-10-19 운영진 설정과 제한된 메일 시험 도구

사용자는 공개 운영 문의 계정에 운영진 권한 부여와 해당 주소만을 대상으로 운영진/심판 요청 메일 수동 시험을 요청했다. 가입·개인정보 저장소 승인·시즌·리그 메일 자동 발송은 모두 닫힌 상태를 유지한다.
