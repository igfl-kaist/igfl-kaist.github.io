# IGFL 리그 구현·운영 인계

기준일: 2026-10-16. 확정된 정상 경기·팀 운영 흐름을 구현했다. 실제 선수 가입과 시즌을 개통한 상태는 아니다. 개인정보 정책을 확정하기 전에는 합성 데이터만 사용한다.

| 영역 | 구현 내용 |

| 공개 화면 | 소개 홈, 팀 Elo, 선수별 최근 출전 5경기 득점·심판 공로 공동 상위 3위, 팀 카드·상세, 선수 카드·전체/팀 소속/무소속/심판 필터 |
| 디자인 | 흰 배경·짙은 초록색, OUR LAB. OUR TEAM., 주황색 모집 배지, 기본 팀 이미지와 업로드 이미지, 반응형 표·명단·폼 |

주장은 부주장으로 대체 확인 가능하다. 양 팀 확인은 두 대표 모두의 확인을 뜻하지 않는다. 대표 겸 심판이면 선수·팀 관리·일정·결과·심판의 다섯 탭을 모두 본다. 경기 상세 전체의 일반 공개 정책은 미정이라 공개 API에는 개인별 경기 명단을 내리지 않는다. 참가 팀의 일반 선수에게도 상세 제출 자료 대신 일정 메타데이터와 본인 기록만 제공한다.

## 코드와 저장 구조

- `server/league.mjs`: 환경 독립적인 리그 명령·권한·상태 전이·조회·집계. 잘못된 명령은 원본 상태를 변경하지 않는다.
- `server/images.mjs`: 이미지 MIME·실제 파일 서명·크기·해상도 검증.
- `apps-script/LeagueAdapter.gs`: 기존 인증 서버 세션·ScriptLock·비공개 Sheets와 연결한다.
- `src/league-ui.mjs`, `src/league.css`: 실제 서버 데이터로 렌더링하는 화면과 역할별 조작. 30초 주기 및 온라인/탭 복귀 시 갱신한다. 서버 push 방식은 아니다. 입력 중에는 폼을 덮어쓰지 않고 변경 안내를 표시한다.
- `dev/`, `scripts/dev.mjs`: 같은 엔진을 실행하는 localhost 합성 검증 서버. 임의 계정 선택은 이 환경에서만 가능하며 정적 빌드에 포함되지 않는다. 서버 직렬 큐와 임시 파일 rename으로 저장한다.

현재 파일럿은 공개 선수 목록과 비공개 프로필을 서로 다른 배열에 두고, API에서 허용한 필드만 투영한다. 동일한 소유자 전용 시트에 저장하지만 일반 이용자에게 시트를 공유하지 않는다. 공개 클라이언트가 개인정보를 내려받아 숨기는 방식이 아니다. 세션 토큰 원문은 저장소·시트에 넣지 않는다.

### 리그 저장소 초기화와 버전 갱신

1. 기존 인증 프로젝트·인증 시트를 유지한다. `initializeAuth()`를 다시 실행하지 않는다.
2. `node scripts/build-gas.mjs`로 만든 `.local/AppsScript.gs`를 편집기 `Code.gs`에 저장한다. 기존 `appsscript.json`의 두 OAuth 범위는 그대로다.
3. 소유자가 `initializeLeagueStorage()`를 한 번 실행한다. `LeagueSnapshots` 탭과 최초 상태만 추가한다. 이미 있으면 유지한다. 웹 API에서는 이 함수를 호출할 수 없다.
4. 기존 웹 앱 배포를 새 버전으로 갱신한다. 소유자 실행·모든 사용자 호출 설정, `/exec` 주소는 유지한다.
5. 초기 상태는 선수/팀 0, 가입 닫힘, 시즌 준비다. 합성 샘플을 실제 서버에 넣지 않는다.

`LeagueSnapshots`에는 JSON 전체 상태를 UTF-8 base64로 인코딩하고 `IGFL:` 접두사를 붙여 32,000자 단위로 저장한다. 텍스트 형식과 접두사는 시트 수식 실행을 막고 한글·이모지 분할 손상을 피한다. 모든 조각 기록·flush 후 `LEAGUE_ACTIVE_SNAPSHOT` 속성 하나를 바꾸는 지점에서 커밋한다. 중간 실패는 기존 스냅샷을 유지한다. 명령과 첫 심판 수락·경기 최종 확정은 같은 ScriptLock 안에서 실행한다.

**용량·운영 한계:** 상태 원문 4,000,000자에서 저장을 거부하며 과거 스냅샷은 자동 삭제하지 않는다. 이미지도 상태 안에 있으므로 팀 수·이미지 변경·경기·감사 이력이 늘면 시트가 빠르게 커진다. 현재는 적은 인원의 파일럿 어댑터다. 실제 모집 전 예상 인원·요청량·메일 할당량을 점검하고, 장기 운영은 DB와 객체 이미지 저장소 분리를 검토한다. Apps Script/Sheets의 무료 한도가 항상 충분하다고 보장하지 않는다.

### 운영 설정

모두 Apps Script의 **Script Properties**에 넣는다. 실제 값은 저장소에 기록하지 않는다.

| 속성 | 기본값과 용도 |
| --- | --- |
| `LEAGUE_REGISTRATION_OPEN` | 기본 false. 아래 정책과 인증 허용 범위를 확인한 뒤에만 true |
| `PRIVACY_VERSION` / `PRIVACY_NOTICE` | 기본 빈 값. 최종 수집·이용 동의 버전과 안내 본문. 가입 열림 외에 이 두 값도 있어야 서버가 등록 허용 |
| `LEAGUE_SEASON_ID` / `LEAGUE_SEASON_NAME` | 기본 pilot / 시즌 준비. 시즌 ID는 경기 기록 귀속 키이므로 임의 교체 금지 |
| `LEAGUE_SEASON_OPEN` | 기본 false. 시즌 운영 합의 후 true로 일정 등록 허용 |
| `TEAM_GRACE_DAYS` | 기본 60. 인원 미달 유예의 기술 기본값. 운영 결정 시 양의 정수로 조정 |
| `LEAGUE_ADMIN_USER_IDS` | 운영진 내부 사용자 ID를 쉼표로 구분. 브라우저에서 제출한 admin 값을 사용하지 않음 |
| `LEAGUE_ADMIN_EMAILS` | 운영진 알림 수신 주소. 관리자 권한 부여와 별개 |
| `LEAGUE_SITE_URL` | 실제 이용자가 접속할 홈페이지 URL. 알림의 링크에 사용 |
| `LEAGUE_EMAILS_ENABLED` | 기본 false. 수신자·홈페이지·트리거 준비 후 true |

최초 운영진은 먼저 허용된 이메일로 로그인한 후 소유자가 비공개 인증 시트의 해당 Sessions 레코드에서 `userId`를 확인해 설정한다. 이메일을 내부 ID 대신 넣으면 권한이 생기지 않는다. 운영진 자신은 선수 미등록이어도 운영 관리가 가능하다. 사용자에게 관리자 선택 항목을 제공하지 않는다.

2026-10-16 사용자 승인으로 `AUTH_EMAIL_SCOPE=kaist`를 적용해 정확한 `@kaist.ac.kr` 인증을 허용했다. 하위 도메인·유사 도메인은 계속 거부한다. 소유자 도구 `allowKaistEmailAuthentication()`은 선수 가입이 닫혀 있을 때만 이 범위를 변경하며 가입·시즌을 열지 않는다. `pilot`으로 제한하면 `PILOT_EMAILS` 목록을 다시 강제한다. 이메일은 정규화하고 학번/사번은 앞뒤 공백 제거 후 중복 거부한다. 별칭 병합·식별번호 변경은 자동 처리하지 않는다.

유예 만료 정리는 API 요청 시 실행하므로 트래픽이 없으면 다음 요청 때 적용된다. 마감 시각의 자동 통보를 보장하는 스케줄러는 아직 없다.

### 메일 작업과 장애 대응

심판 후보마다 별도 작업을 기록하며, 팀 신청·자격 확인·이의·불일치·외부 경기 승인 대기는 운영진 작업으로 기록한다. 경기 수락·결과 확인은 홈페이지 안에서만 진행한다. 메일에 선수의 비공개 프로필이나 전체 경기 기록을 넣지 않는다.

`processLeagueEmails()`를 소유자가 수동 실행해 확인한 뒤 Apps Script 시간 기반 트리거에 연결한다(예: 1분 간격). 실행당 최대 10건, 작업당 시도 상한 3회. 잔여 MailApp 할당량·수신자가 없으면 작업을 pending으로 유지한다. 잠금 안에서 sending으로 선점하고 메일 발송은 잠금 밖에서 수행한다. 성공은 sent, 발송 예외는 uncertain이다. 중간 실행 종료로 남은 sending도 확인 대상이다.

MailApp에는 멱등 발송 키가 없어서 예외/시간 초과가 실제 미수신을 뜻하지 않는다. **uncertain/sending은 자동 재발송하지 않는다.** 운영진이 발송함과 알림 ID를 확인한 뒤 소유자 도구로 작업을 복구해야 한다. 현재 웹 관리 화면은 상태 확인만 제공한다. 시트 조각을 직접 편집하지 말고 잠금·새 스냅샷 절차로 복구한다. 자동 트리거 설치와 실제 심판/운영진 메일 수신 검증은 아직 하지 않았다.

### 백업과 복구

실제 개통 전 소유자 전용 Drive 폴더에 인증 시트 복사본과 Script Properties의 비공개 백업을 준비하고 접근자를 확인한다. 비밀키는 GitHub·채팅에 복사하지 않는다. 보관 기간은 개인정보 정책과 함께 정한다. 현재 자동 백업·보관기한·복구 관리자 UI는 없다.

부분 쓰기는 이전 포인터로 자동 보호된다. 저장 장애 시 먼저 쓰기를 중지하고 현재 포인터·마지막 정상 조각을 보존한다. 이전의 완전한 스냅샷으로 되돌리려면 해당 revision·JSON 길이·행 범위를 검증하고 ScriptLock 안에서 포인터를 복원한다. 이후 승인·소속·Elo·메일 작업의 유실과 재발송 가능성을 함께 확인한다. 전체 시트 복사본 복원은 OTP/세션도 되돌리므로 기존 세션을 폐기하는 복구 절차가 필요하다. 시험 복구 전 실제 운영 데이터로 실행하지 않는다.

## 이미지·보안·충돌 처리

브라우저는 JPG/PNG/WebP 입력 최대 3MB를 받아 긴 변 512px JPEG로 최적화하고 메타데이터를 제거한다. 서버는 data URL·base64·실제 이미지 서명·최대 1024px·디코딩 150KB를 다시 검사한다. SVG는 받지 않는다. 팀 관리에서 기본 이미지로 복원 가능하다.

모든 명령은 서버에서 역할·대상·선수 자격·정원·심판 중립성을 검증한다. 전역 revision과 경기 버전이 달라지면 쓰기를 거부하고 최신 기록을 다시 불러오도록 안내한다. 기록 수정은 양 팀의 기존 확인을 해제한다. 불일치/이의 검토 중에는 최종 승인이 불가능하다. 확정 경기는 중복 요청해도 Elo를 다시 반영하지 않는다.

확정 후 정정·취소·몰수·시즌 이월·컵 운영은 세칙이 미정이라 정상 경기 확정으로 우회하지 않는다. 확정 기록은 현재 불변이며 확정 후 이의 처리 기능도 세칙 확정 뒤 추가한다. 향후 정정 기능에서도 시간순 재계산과 새 확인 이력이 필요하다.

## 검증 기록과 개통 전 과제

자동 테스트 36개: 인증 12개, 리그 도메인 19개, 실제 localhost HTTP/재시작 1개, Sheets 스냅샷·메일 모형 4개. 권한 상승 거부·비공개 투영·중복 소속 경쟁·이적 없는 탈퇴·유예·대표 교체·심판 첫 수락·스코어 불일치·버전 재확인·외부 승인·중복 Elo·최근 출전 5경기·공동순위·이미지 검증·부분 저장 실패·메일 중복 방지를 포함한다. Google 서비스 모형 테스트와 실제 Google 시험을 구분한다.

브라우저 합성 검증: 양 팀 대표가 자기 명단/득점과 2:1 제출 → 양 팀 현재 버전 확인 → 배정 내부 심판 최종 승인 → 팀 Elo·득점·심판 공로 갱신. 교직원 등록(사번·지도교수 없음), 역할 탭, 방출 팝업 취소, 이미지 업로드/새로고침 유지/기본 복원, 심판 필터를 확인했다. 무소속 선수 6명으로 새 팀을 신청하고 운영진 계정에서 승인해 공개 팀/랭킹에 반영되는 흐름도 확인했다. 390×844에서 랭킹과 일정·명단 폼을 확인했다. 테스트 데이터는 `.local/`에만 남는다.

실제 Google: 기존 소유자 전용 인증 시트에 `initializeLeagueStorage()` 성공, 기존 웹 앱의 리그 서버 새 버전 반영, 로그인하지 않은 로컬 브라우저에서 공개 리그 읽기 성공. 실제 선수 개인정보·리그 명령·심판 알림 메일은 전송하지 않았다. 실제 Apps Script에서 여러 사용자 동시 수락까지 검증했다는 뜻은 아니다.

개통 전에는 아래를 이어서 진행한다.

1. 개인정보 안내·보관/철회/탈퇴·과거 이름 처리 확정 후 실제 가입을 열고 인증 허용 범위 확대.
2. 최초 운영진·수신자 지정, 실제 심판 요청/운영진 메일과 실패 복구 확인, 시간 트리거 설치.
3. 시즌 ID·기간·유예일 확정. 확정 후 정정·일정 변경·취소 등 예외 세칙은 별도 결정.
4. 공개 Pages 출처 CORS·모바일·세션 검증 기록 확인, 실제 서버의 동시 수락/확정·저장 장애 추가 점검.
5. 운영 규모에 맞는 장기 저장·백업·보관 정책과 비용 확인. 상위 8팀 대회·컵은 규칙 확정 후 추가.
