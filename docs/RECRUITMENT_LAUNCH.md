# 선수·팀 모집 시범 운영 인계

2026-10-19 사용자 결정과 개통 범위 답변에 따르며 16:28 KST 실제 개통을 완료했다. 배포 버전 13/코드 0.6.0, 가입 true·시즌/자동 리그 메일 false와 최신 안내를 확인했다. 선수 등록·팀 신청을 먼저 개통하고 경기 일정 등록과 리그 자동 메일은 닫는다. 팀 신청은 홈페이지 운영 관리에서 확인하며 자동 이메일을 기대하지 않는다. 일반 사용자에게 운영진 권한을 부여하거나 선수/팀 승인 규칙을 바꾸지 않는다.

## 개인정보 운영 결정

기존 Sheets·Script Properties를 유지한다. 탈퇴 시 현재 개인 정보/연결/세션을 정리하고 정리된 현재 데이터만 새 빈 시트에 기록·재조회 검증 후 전환한다. 운영자는 이전 파일·사본·휴지통을 수동 파기하고 남은 파일이 있으면 파기 완료로 안내하지 않는다. 삭제 자료의 복구를 요청하거나 복원해서 사용하지 않는다. 다른 관리자의 복구 등으로 다시 나타난 자료는 서비스에 재적용하지 않고 접근 차단·삭제 재적용·검증을 거친다. 원시 파일·Properties 덤프 복원 및 자동 영구 삭제 기능을 추가하지 않는다.

운영자가 직접 관리하지 못하는 Google 관리자 복구·Vault·외부/공급자 백업의 적용 범위와 실제 처리/보관 국가·계약 주체는 계속 확인 항목이다. 수동 파기와 복원 금지 결정이 Google 물리적 삭제를 증명하거나 외부/법적 검토를 대신하지 않는다. 안내에 이 제한을 숨기거나 확인되지 않은 국가/삭제 기간을 채우지 않는다. 처리 조건 확인과 운영 규모 증가에 따라 저장·권한·인계 체계를 보완한다.

공통 원본 `src/privacy-content.mjs`의 수집/공개 동의 v3를 서버와 양식에 적용한다. 두 동의는 여전히 별도 필수이며 공개 비동의의 익명 가입을 추가하지 않는다. 생년월일은 수집하지 않는다. 운영 연락처는 sy.choi@kaist.ac.kr이다.

## 인증 발송 예산

`IGFL_.dailyBudget=300`으로 전체 최근 24시간 인증 발송 **예약 횟수**를 제한한다. 성공 로그인 300명을 보장하거나 Google 계정 한도를 늘리는 설정이 아니다. 재발송·실패 예약도 예산에 들어간다. 이메일별 5회/시간, 재요청 60초, 인증번호 5분과 5회 실패 차단은 유지한다. Google 잔여 수신자 한도가 먼저 부족하면 발송을 거절한다. 유효 세션 12시간 동안 코드를 다시 요청하지 않는다. 운영진/심판 메일과 다른 프로젝트 발송도 동일 계정 Google 한도를 쓸 수 있다.

공식 Workspace MailApp 기본 한도는 1,500 수신자/일, 일반 계정 100이며 시험판·추가 제한/변경 가능성이 있다. 실제 계정의 잔여량은 소유자 진단으로 확인한다. 100개 계정과 300개 요청·세션의 대표 크기 저장 검증은 400,000바이트 미만을 확인하며 값/전체 420,000바이트 방어선을 유지한다. 긴 이메일·더 큰 데이터까지 무제한 지원한다는 뜻은 아니다.

## 소유자 개통 순서

1. `node --test`, 정적/GAS 빌드를 통과한 번들을 같은 Google 프로젝트에 저장한다. URL·소유자 실행·모든 사용자 호출과 기존 OAuth 두 범위·시간별 개인정보 정리 트리거를 유지한다.
2. `configureManualDeletionPolicy()`로 최신 안내·문의처·수동 파기 결정 버전을 준비한다. 네 개 개통 스위치가 닫혀 있어야 하며 준비만으로 가입/승인을 열지 않는다.
3. `verifyRecruitmentRules()`로 동일 GAS 실행 환경의 **메모리 안에서만** 합성 가입·동의 저장·비공개 투영·탈퇴를 검증한다. 실제 선수·인증 계정·시트·파일·메일은 만들지 않는다. 이것은 실제 이용자의 전체 OTP→가입→파일 전환 시험과 구분한다.
4. `inspectRecruitmentLaunch()`로 KAIST 인증·Properties 이전 완료·운영진 연결·최신 안내·수동 정책·삭제 대기 0·진행 중 탈퇴/전환 없음·최근 2시간 이내 정리 성공·프리시즌 준비·경기/자동 메일 닫힘·메일 잔여량·속성 용량을 확인한다. 비밀값/사용자 ID/선수 정보는 출력하지 않는다. 실패 시 가입을 열지 말고 해당 항목을 복구한다.
5. 기존 웹 앱을 새 버전으로 갱신하고 공개 화면/처리방침/동의 버전과 서버의 일치를 확인한다. `openPlayerRecruitment()`는 모든 사전 검증이 통과해야 `PRIVACY_STORAGE_APPROVED`와 `LEAGUE_REGISTRATION_OPEN`만 true로 설정한다. 이 플래그는 운영자의 위 시범 운영 결정을 뜻한다. 외부 기관의 승인 기록이 아니다.
6. 공개 리그 응답의 가입 true·시즌 false, 최신 동의 버전과 안내를 확인한다. 자동 메일 false도 소유자 진단에서 확인한다. 팀은 기존 6~20명·운영진 승인과 권한 규칙을 따른다. 홈페이지에 합성 검증 계정 선택기를 넣지 않는다.

긴급 중단은 소유자 `closePlayerRecruitment()`로 가입/저장소 승인 두 플래그만 false로 돌린다. 회원 데이터·동의·운영진 권한·시즌/자동 메일 설정을 삭제하지 않는다. 이미 등록한 선수의 팀 운영/신청은 기존 권한 흐름이므로 전체 서비스 중지가 필요하면 별도 조치한다.

## 검증 범위

자동 테스트 87개를 통과했다. 300회 예약 경계·24시간 경과 후 재개·작은 Google 잔여량 조기 차단, 기존 시간별/재요청 제한 유지, 100명+300요청/세션 저장 용량, 개통 전 검사·부분 개통/중단·API 비노출과 메모리 가입/탈퇴를 포함한다. 실제 Google·Pages 적용 결과는 [배포 기록](AUTH_DEPLOYMENT.md)에 추가한다. 실제 선수 정보나 테스트 인증 메일을 임의로 발송하지 않는다.
