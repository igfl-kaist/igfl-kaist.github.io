# IGFL Codex agent 최종 구현 지침

기준일은 2026년 10월 16일이다. 이 지침은 IGFL 홈페이지의 확정 기능과 승인된 디자인을 실제 서비스로 구현할 개발 agent에게 전달한다. 사용자 지시에 따라 실제 구현을 시작했다. 소개·로그인 화면과 Apps Script 인증 서버 초안 및 로컬 테스트를 만들었으며, 실제 메일·세션 연동과 전체 리그 기능은 아직 검증 전이다. 현재 구현·배포 상태는 [README](../README.md)와 [인증 배포 안내](AUTH_DEPLOYMENT.md)를 따른다. 아래 내용은 전체 구현 목표이며 완료 목록이 아니다.

이번 요청은 지침서 정리이며 구현 시작 지시가 아니다. 사용자가 후속으로 구현을 지시하면 아래 범위 안에서 작업한다. 시안의 버튼 동작을 실제 인증·권한·저장 구현으로 간주하지 않는다.

## 읽을 자료와 적용 순서

1. 저장소의 `AGENTS.md`를 읽고 현재 작업 허용 범위를 확인한다.
2. 이 문서로 전체 기능, 디자인, 구현 순서와 완료 기준을 파악한다.
3. [서비스 기획안](PRODUCT_SPEC.md)과 [UI와 UX 기획](UI_UX.md)에서 세부 요구를 확인한다.
4. [미정 사항과 기술 제안](DECISIONS.md)을 읽고 확정 규칙과 제안을 구분한다.
5. [승인된 시안 원본](design/igfl-approved-mockup.html)의 화면·문구·간격·상태 표현을 참고한다. 사용 방법과 주의점은 [시안 안내](design/README.md)에 있다.

최신 사용자 지시가 우선한다. 문서와 시안이 다르면 이 문서와 확정 요구를 기능 기준으로 삼고 차이를 기록한다. 시안의 예시값이나 검토 버튼으로 운영 정책을 정하지 않는다. 미정 사항은 필요한 시점에 묶어서 확인하고, 답과 무관한 작업은 계속한다.

## 서비스 범위

리그명은 **IGFL**, 영문명은 **ISE & GSDS Futsal League**다. 학교 도메인이나 KAIST SSO에 의존하지 않고 독립적으로 운영한다. 팀들이 자율적으로 경기를 잡고, 심판이 진행한 경기의 결과를 양 팀과 최종 승인자가 확인하면 팀 Elo와 기록에 반영한다.

첫 화면은 **리그 소개 홈**이다. 파워랭킹을 첫 화면으로 바꾸지 않는다. 공개 하위 페이지로 랭킹보드, 팀 목록과 상세, 선수 목록을 제공한다. 로그인 후 선수 활동, 팀 운영, 경기 일정·결과, 심판 활동과 운영진 관리를 제공한다.

정기 리그 대진 자동 편성, 개인 Elo, 전체 개인 득점 순위, 홈페이지 결제·송금·정산, 팀 대표 연락처 공개, 범용 실시간 채팅은 요청 범위가 아니다. 팀 가입 문의·요청은 홈페이지 요청함으로 처리한다. 토너먼트·컵 자동 운영은 대회 세칙 확정 후 확장한다.

## 선수 자격과 등록

### 참가 자격

다음 중 하나를 충족하는 사람만 선수로 등록한다.

- GSDS 또는 ISE 소속 대학원생.
- GSDS 또는 ISE 소속 교직원.
- 지도교수가 GSDS 또는 ISE 소속인 다른 학과 대학원생.

기계공학과 대학원생이어도 지도교수가 ISE 소속이면 참가 가능하다. 세 번째 조건을 일반 외부인에게 확대하지 않는다. 외부 심판은 선수 자격과 별도로 허용한다.

### 가입 흐름

`KAIST 공식 이메일 입력 → 6자리 인증번호 발송 → 인증번호 검증 → 선수 정보와 동의 입력 → 즉시 선수 등록` 순서다. 운영진의 사전 가입 승인은 없다. 자격은 본인이 신고하고 의심 사례·확인 요청만 운영진이 별도로 검토한다. 이메일 소유 확인을 학과·재학 상태의 자동 검증이라고 안내하지 않는다.

- 인증번호는 **숫자 6자리 난수**, 유효시간은 **발급 후 5분**이다. 앞자리 0도 보존한다.
- 숫자 키패드와 코드 붙여넣기·자동완성을 지원하는 입력란, 남은 시간, 재발급과 만료 상태를 제공한다.
- 난수 생성·검증·만료는 서버에서 수행한다. 코드와 이메일·인증 시도를 연결하고 일회 사용과 재발급 시 이전 번호 무효화를 강제한다.
- 이메일 변경 시 다시 인증한다. 코드 원문을 공개 응답·화면·로그에 노출하지 않는다. 시안의 체험용 코드 표시는 실제 서비스에서 제거한다.
- 5분은 인증번호의 유효시간으로 해석했다. 인증 이후 정보 입력까지 5분으로 제한하지 않는다. 전체 가입 제한 시간이 필요하다면 사용자에게 확인한다.
- 인증 재발송 간격·오입력 제한·발송 제한은 기술 설정으로 정한다. 시안의 오입력 5회는 운영 확정값이 아니다.

가입과 이후 로그인 모두 **KAIST 이메일 숫자 6자리·5분 인증**을 사용한다. 비밀번호 설정·비밀번호 로그인·비밀번호 찾기를 만들지 않는다. Apps Script와 비공개 Sheets를 인증 백엔드로 우선 사용한다. 인증 성공 시 실제 세션을 발급하고 모든 보호 API에서 검증하며 유효 세션 안에서는 메일을 반복 발송하지 않는다. 기존 선수는 내 선수 활동, 미등록자는 정보·동의 입력으로 연결한다. [Apps Script 인증 설계](AUTH_APPS_SCRIPT.md)의 CORS·발송 한도·세션·권한 검증을 구현 첫 단계에 확인한다.

### 수집 정보와 공개 범위

| 정보 | 입력과 처리 | 열람 범위 |
| --- | --- | --- |
| KAIST 이메일 | 필수 인증, 기본 허용은 정확한 kaist.ac.kr | 본인·운영진 |
| 이름 | 필수 | 공개 |
| 참가 구분과 실제 학과·부서 | 자격 신고를 구분 | 본인·운영진 |
| 학번 또는 사번 | 대학원생 학번, 교직원 사번, 문자열로 보관 | 본인·운영진 |
| 생년월일 | 필수 | 본인·운영진 |
| 지도교수 | 대학원생 입력, 교직원은 해당 없음 | 본인·운영진 |
| 소속 연구실 | 공개 프로필과 명단에 사용 | 공개 |
| 심판 가능 여부 | 가능·불가능, 언제나 해당 경기 중립성은 별도 검증 | 공개 표시·필터 |
| 소속 팀 | 선택, 무소속 가능 | 공개 소속 관계 |

교직원이 연구실이 없을 때 부서를 대신 표시할지는 미정이다. 가입 화면에서 팀을 선택했다고 곧바로 팀 소속을 만들지 않는다. 팀 가입·영입 확인 절차에 연결한다. 한 계정·선수의 중복 등록 방지 기준과 학번·사번 변경 대응은 구현 전 정한다.

프로필 단계에는 짧은 **개인정보 수집 및 이용 동의**를 필수 체크박스로 받는다. 기본 체크는 해제하고 미동의 등록을 차단한다. 목적·항목·공개 범위를 안내하며 동의 문안 버전과 시각을 기록한다. 보관 기간, 탈퇴·삭제와 과거 기록 처리, 최종 문안은 실제 개인정보 수집 전에 확정해야 한다.

심판 가능 여부 옆에는 **경기당 수당 20,000원, 각 팀이 10,000원씩 심판에게 직접 지급**한다고 표시한다. 운영진이 수당을 수납·지급하는 것으로 쓰지 않는다.

## 팀 등록과 운영

- 등록 선수 **6명 이상 20명 이하**와 주장·부주장 정보를 갖춰 팀 등록을 신청한다. 운영진 승인 후 정식 팀이 된다.
- 선수는 동시에 한 팀에만 소속된다. 별도 이적 요청·승인 기능을 만들지 않는다. 선수가 기존 팀을 탈퇴해 무소속이 된 뒤 새 팀에 영입된다.
- 주장과 부주장은 같은 팀 관리·영입·방출·경기 등록·결과 확인 권한을 갖는다. 두 사람이 모두 확인할 필요 없이 한 명이 팀을 대표한다.
- 모집 중 여부는 팀 대표가 관리한다. 공개 팀 카드·상세에는 **주황색 선수 모집 중 배지**를 표시한다.
- 무소속 등록 선수는 팀 상세에서 주장·부주장에게 홈페이지 가입 문의·요청을 남긴다. 문의만으로 소속이 생기지 않고 대표의 개인 이메일·전화번호를 공개하지 않는다.
- 영입·팀 승인 시 정원과 단일 소속을 서버에서 재검사한다. 서로 다른 두 팀의 동시 영입도 중복 소속으로 이어지면 안 된다.
- 팀 대표 이미지는 **팀 관리 → 팀 프로필**에서 업로드한다. 업로드 이미지가 있으면 팀 카드·상세에 사용하고 없으면 승인 시안의 기본 이미지를 사용한다.
- 방출은 선수 이름을 표시한 **취소 / 방출하기** 팝업에서 한 번 더 확인한다. 취소·닫기는 아무 변화가 없어야 한다. 과거 출전·득점·당시 소속 기록은 보존한다.
- 팀이 6명 미만이면 즉시 팀을 퇴출하지 않고 리그 참가 유예로 전환한다. 유예 중 공식 경기와 현재 순위 참여를 보류하고 충원은 허용한다. 사용자 범위인 1~2개월 안에서 **60일을 기본안**으로 두며 운영 설정으로 바꿀 수 있게 한다. 기한 내 6명 이상이면 복귀하고 끝까지 미달이면 팀을 리그에서 제외한다. 팀·선수 계정과 과거 기록을 삭제하지 않는다. 제외된 팀 소속의 일괄 무소속 전환·재등록은 아직 정하지 않았으므로 자동 대량 방출하지 않는다. 20명을 넘는 영입은 막는다.

영입 동의는 팀 안에서 협의하고 주장·부주장이 시스템에 등록한다. 별도의 선수 동의 승인 단계를 강제하지 않는다. 영입 시 대상이 무소속인지와 정원을 다시 검사한다. 팀 대표에게 선수의 비공개 정보 열람 권한을 추가하지 않는다.

**내 선수 활동 → 팀 탈퇴**에서 팀명과 ‘취소 / 탈퇴하기’ 팝업을 표시한다. 확인 즉시 대표 승인 없이 무소속이 되고 팀 권한을 해제한다. 선수 계정·과거 출전 기록은 보존하고 새 팀 가입 요청을 허용한다. 주장·부주장도 본인 탈퇴는 막지 않으며 즉시 권한을 잃는다. 공석은 잔존 대표 또는 운영진이 새 대표 승인 절차로 복구하고 떠난 사람의 권한을 유지하지 않는다.

팀 등록 시 주장·부주장을 지정한다. 이후 기존 주장·부주장은 팀 관리에서 협의한 새 주장·부주장을 등록해 **대표 교체 요청**을 보낸다. 운영진 승인 시점부터 함께 권한을 바꾸고 승인 전에는 기존 대표가 유지된다. 후보는 현재 소속 선수이고 서로 다른 사람으로 선택한다. 승인 직전 소속·공석·요청 버전을 다시 검사하며 후보 탈퇴 시 오래된 요청으로 권한을 부여하지 않는다. 운영진은 홈페이지 대표 교체 요청함에서 승인·보완과 이력을 관리한다.

## 경기 일정과 심판 배정

### 공식 경기 규칙

| 항목 | 규칙 |
| --- | --- |
| 대진과 일정 | 팀끼리 자율 협의, 경기 전 홈페이지 등록 |
| 경기 인원 | 5대5 |
| 경기 시간 | 전반 20분 · 휴식 5분 · 후반 20분 |
| 교체 | 무제한 |
| 동점 | 승부차기로 최종 승자 결정, 연장전은 요구되지 않음 |
| 심판 | 필수, 양 팀 어느 쪽에도 소속되지 않은 사람 |
| 비용 | 총 20,000원, 양 팀 각 10,000원 직접 지급 |

### 사전 정보와 명단

주장·부주장이 상대 팀, 날짜·시작 시간, 장소, 심판 요청 후보 또는 외부 심판 정보, **자기 팀 사전 출전 명단**을 입력한다. 명단은 자기 팀 소속 선수를 자동 표시한 체크박스에서 복수 선택한다. 교체 선수를 포함하므로 전체 명단을 5명으로 제한하지 않는다.

상대 팀의 선수 명단을 대신 고르거나 수정하지 않는다. 상대 팀 대표가 같은 경기 ID에서 자기 명단을 등록한다. 화면 시간은 한국 시간으로 표시한다. 상대 팀의 일정 동의, 중복 경기 생성 방지 방식, 변경·취소와 명단 마감은 아직 세칙을 정해야 한다.

### 내부 심판 동시 요청

1. 양 팀 소속이 아닌 심판 가능 선수를 후보로 보여준다.
2. 대표가 한 명 이상을 **복수 선택**해 동시에 요청한다.
3. 선택된 각 후보에게 홈페이지 요청과 **배정 요청 이메일 알림**을 만든다. 이메일은 로그인 후 해당 요청으로 안내한다.
4. 심판은 홈페이지 심판 활동에서 일시·장소·대진·비용을 확인해 수락 또는 거절한다.
5. 서버가 처음 유효하게 수락 처리한 한 명만 담당 심판으로 확정한다. 나머지 요청은 종료한다.
6. **배정 전에는 공식 일정 등록을 보류**하고 대기 일정·명단을 보관한다. 배정이 끝나면 공식 등록 상태로 전환한다.

동시 수락은 트랜잭션 또는 조건부 갱신과 유일성 제약으로 한 명만 확정한다. 클라이언트 클릭 시각이나 이메일 도착 순서로 담당자를 정하지 않는다. 종료된 요청, 늦은 수락, 변경·취소된 일정 버전의 수락은 차단한다. 수락 시에도 현재 적격성을 검사하고 경기 당시 소속 이력과 연결한다. 메일 열람이나 링크를 여는 행위 자체는 수락이 아니다.

전원 거절·미응답·요청 만료·같은 시간 중복 배정·변경 후 재요청 정책은 미정이다. 무응답을 자동 수락으로 바꾸지 않는다. 시안의 대진·일시·장소 변경 시 요청 초기화는 보수적인 예시다.

### 외부 심판

외부인도 심판이 가능하며 선수 자격을 맞춘 회원가입을 강제하지 않는다. 배정 확인 방식은 미정이고 시안은 대표가 이름과 수락 확인을 기록한다. 외부 심판 배정이 확인되지 않은 일정도 공식 등록을 보류한다. 경기 후 최종 승인자는 운영진이다. 별도 외부 심판 계정이나 이메일 승인 기능은 확정 범위가 아니다.

## 경기 결과와 최종 확정

각 팀의 주장 또는 부주장이 홈페이지에서 다음을 각각 제출한다.

- 경기 **전체 정규시간 스코어**. 동점이면 승부차기 스코어도 별도로 제출한다.
- **자기 팀 실제 출전 선수**. 자기 팀 체크박스 명단에서 고른다.
- **자기 팀 득점자와 득점 수**. 실제 출전 선수만 선택할 수 있다.
- 해당 팀 대표의 기록 확인.

상대 팀 출전·득점은 읽기 전용이며 대신 작성할 수 없다. 자기 팀 선수 득점 합계와 자기 팀 스코어를 검증한다. 자책골 등 예외는 세칙 확정이 필요하다. 승부차기 골은 개인 정규시간 득점에 합산하지 않는다.

서버는 양 팀이 제출한 스코어를 **같은 팀 순서로 정규화**해서 비교한다. 정규시간과 해당하는 승부차기 스코어가 모두 일치해야 한다. 같은 승자를 적었다고 일치로 처리하지 않는다.

| 상황 | 처리 |
| --- | --- |
| 한 팀 미제출·미확인 | 대기, 최종 승인 불가 |
| 양 팀 스코어 불일치 | 확정·Elo 보류, 원본 제출과 버전 보존, 운영진 홈페이지 검토함과 이메일 알림 |
| 이의 제기 | 검토 중 확정 보류, 운영진 개입 |
| 내부 심판 경기와 양 팀 확인·일치 | 배정된 심판이 최종 승인하면 자동 공식 확정 |
| 외부 심판 경기와 양 팀 확인·일치 | 운영진이 외부 심판 확인 후 최종 승인하면 자동 공식 확정 |

확인·승인은 특정 기록 버전과 양 팀 제출 조합에 연결한다. 스코어·실제 명단·득점이 바뀌면 기존 확인과 최종 승인을 무효화하고 양 팀부터 다시 확인한다. 오래된 화면의 승인 요청으로 새 기록을 확정할 수 없어야 한다.

공식 결과, 승인 이력과 Elo 적용은 중복 클릭·동시 요청에도 한 번만 반영한다. 확정된 기록의 정정은 이력과 후속 Elo 재계산을 보존하도록 설계하되 정정 권한·기한·확정 후 이의 세칙은 미정이다. 이의 해결을 한쪽 스코어로 조용히 덮어쓰는 것으로 구현하지 않는다.

## Elo와 개인 기록

- 팀 점수는 상대 전력을 고려하는 **Elo**다. **점수 차는 제외**한다.
- **공식 확정 경기만** 반영한다. 대기·불일치·분쟁 중 경기는 순위에 반영하지 않는다.
- 경기별 반영 전후 점수, 변화, 계산 순서와 규칙 버전을 남기고 재계산을 가능하게 한다.
- 확정 후 다른 이용자가 열어 둔 랭킹 화면도 갱신한다. 연결 복구 시 최신 공식 상태를 다시 읽는다.
- 기본값은 **초기 1000점·K=32·기대 승률 척도 400**, 승리 1·패배 0이며 승부차기도 동일하다. 경기 일시·경기 ID 순서로 계산하고 과거 지연 확정·정정은 재계산한다. 정확한 동률은 공동순위, 표시는 정수 반올림하되 계산은 정밀도를 유지한다. 시즌 이월과 대회 Elo는 미정이다. [계산 규칙](RATING_POLICY.md)을 구현 기준으로 삼는다.
- 개인 득점은 **시즌 내 각 선수의 최근 실제 출전 5경기**를 집계해 상위 3위를 표시한다. 5경기 미만은 실제 출전 수로 표시한다. 동률은 공동순위와 경계 동률 전원 포함, 0골은 제외한다. 팀을 옮겨도 선수 기록은 이어진다.
- 심판 공로는 **시즌 내 공식 확정된 내부 심판 담당 경기 수 상위 3위**다. 동률은 같은 규칙이고 단순 요청·수락, 미확정 경기와 외부 심판은 기본 보드에서 제외한다.

10월 말 또는 11월 상위 8개 팀 토너먼트·컵 대회와 이후 약 3개월 휴지기는 운영 구상이다. 정확한 날짜, 컵과 토너먼트의 관계, 시드·참가 조건, 컵 Elo와 휴지기 인정 여부는 아직 정하지 않았다. 시즌과 소속 이력은 보존하되 자동 대회 진행을 임의 구현하지 않는다.

운영진 팀 신청 화면은 인원·대표·명단을 보고 승인 또는 보완 요청한다. 외부 심판 결과는 양 팀 확인·스코어 일치와 외부 심판 확인을 거쳐 최종 승인한다. 이의·불일치는 원본을 비교하고 사유를 남겨 재제출을 요청한다. 보완·재제출에는 사유를 요구하고 이력을 남긴다. 불일치·분쟁 중 최종 승인 버튼은 비활성화하며 서버 요청도 거절한다.

팀 등록 신청과 선수 자격 예외 검토 등 시안에 상세 폼이 없는 화면도 같은 디자인 체계로 구현한다. 별도 이적 승인 화면은 추가하지 않는다.

## 이메일과 알림

| 대상 | 발송할 메일 |
| --- | --- |
| 가입·로그인 이용자 | KAIST 학교 이메일 6자리 인증번호 |
| 선택된 내부 심판 후보 | 경기 배정 요청 알림 |

팀 대표의 가입 문의·일반 일정·결과 확인 요청과 경기 확정 안내 메일은 추가하지 않는다. 최초 가입 이후 로그인 코드도 이메일 범위에 포함한다. 비밀번호 복구 메일은 없다. 대표 교체는 우선 홈페이지 요청함에서 관리하고 별도 이메일 종류는 늘리지 않는다. 운영진 수신 주소와 발신 도메인·메일 서비스는 미정이다.

홈페이지 기록을 먼저 보존하고 메일 발송은 실패 재시도·중복 방지를 갖춘 별도 처리로 연결한다. 메일 실패가 경기 요청이나 승인 상태를 없애지 않아야 한다. 실수신자에게 테스트 메일을 보내기 전에는 대상·내용을 확인한다. 홈페이지에서는 실제 요청·처리 상태를 표시하고 시안의 ‘실제 전송 안 함’ 문구를 운영 화면에 남기지 않는다.

## 기술 구현 원칙

프런트엔드는 React·TypeScript·Vite와 GitHub Pages를 후보로 유지한다. **인증·메일은 Google Apps Script와 비공개 Google Sheets를 우선 검증**한다. 리그 경기·Elo 전체 저장소가 자동으로 Sheets로 확정된 것은 아니다. 별도 PostgreSQL 등 리그 API를 쓴다면 Apps Script 세션을 그 서버에서도 검증하는 연결이 필요하다. 기술별 최신 지원·한도를 확인하고 선택한 통신과 저장소가 원자적 심판 배정·권한·Elo 재계산을 충족해야 한다. [인증 설계](AUTH_APPS_SCRIPT.md)를 먼저 읽는다.

**사용자의 기존 개인 GitHub 계정 안에 별도 비공개 저장소 `noeyusiohc/igfl`**을 사용한다. 기존 개인 홈페이지를 덮어쓰지 않고 새 Organization이나 별도 공유 계정을 만들지 않는다. 현재 플랜이 비공개 Pages를 지원하지 않으므로 공개 전환·유료 변경 없이 호스팅 방향을 정한다. 전체 리그 백엔드 제공자는 미정이다. 홈페이지 이용자에게 GitHub 계정은 필요 없다.

공개 저장소의 Pages는 GitHub Free에서 무료로 사용할 수 있고 프로젝트 기본 주소는 `<계정>.github.io/<저장소>/`다. 비공개 저장소 Pages는 지원 유료 플랜이 필요하며 실제 사용 플랜은 구현 시 확인한다. DB·메일·인증·이미지와 독립 도메인 비용은 별개다. [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)를 확인했다.

Pages에는 공개 프런트엔드를 두고 Apps Script가 발송·검증·세션을 처리하는 방향이다. `ContentService` JSON 반환만으로 브라우저 CORS가 해결됐다고 가정하지 않는다. 실제 Pages 출처와 Apps Script 배포 URL에서 검증하고 실패하면 HTML Service 인증 화면 등의 대안을 검토한다. 비밀번호 흐름은 제거했다.

- 기존 로컬 `.git`을 유지하고 새 브랜치는 기본 `codex/` 접두사를 사용한다. 실제 구현·원격 생성 권한 범위는 후속 사용자 지시를 따른다.
- GitHub Pages에는 공개 프런트엔드만 배포한다. 영구 데이터, 인증번호 검증, 권한·승인·Elo와 메일 발송은 별도 백엔드에서 처리한다.
- 공개 선수·팀 데이터와 비공개 프로필을 분리한다. 전체 개인정보를 내려받아 화면에서 숨기는 방법을 금지한다. 실시간 구독에도 비공개 필드를 섞지 않는다.
- 팀 정원·단일 소속, 역할, 자기 팀 쓰기, 중립성, 최초 심판 수락, 결과 버전과 유일한 Elo 적용은 서버·DB에서 강제한다.
- 공개 저장소·번들·합성 데이터·로그에 실제 개인정보, 관리자 키, 발송 키나 인증번호 원문을 넣지 않는다. 운영진 권한은 신뢰할 수 있는 별도 경로에서 부여한다.
- 이미지 업로드의 실제 형식·크기·크롭 기준은 확정 후 적용하고 파일 유형·내용·크기를 서버에서도 확인한다. 시안의 로컬 미리보기를 영구 업로드로 대체해야 한다.
- 공개 페이지의 새로고침·직접 URL·프로젝트 하위 경로·인증 복귀 경로를 검증한다. 실패 시 재시도·빈 상태·권한 오류를 사용자에게 이해되는 문구로 표시한다.
- 실제 백엔드 미연결 상태를 실시간 운영 서비스라고 소개하지 않는다. 운영 저장과 합성 데이터 미리보기를 분리한다.

### 보존할 데이터 관계

인증 계정·세션, 비공개·공개 프로필, 동의 이력, 팀 상태·유예 기한, 리더·대표 교체 요청, 소속 기간·가입·탈퇴, 시즌, 경기와 일정 버전, 심판 후보별 요청·담당자, 팀별 사전·실제 명단, 팀별 결과 버전·득점, 확인·최종 승인, 분쟁·정정, Elo 변동과 알림 이력을 구분한다. 별도 이적 승인 테이블을 필수로 만들지 않는다.

현재 팀 관계를 바꿔도 과거 경기 당시 소속·심판 적격성·득점 기록이 달라지면 안 된다. 한 경기의 여러 제출·수정 이력을 한 행 덮어쓰기로 잃지 않는다. 메일 요청·심판 수락·최종 승인 등 상태 변경은 누가 언제 어떤 버전에 수행했는지 남긴다.

## 구현 순서와 완료 기준

1. **결정과 기반**: 저장소 상태·시안·문서를 읽고 [우선 결정 목록](DECISIONS.md)의 당장 필요한 항목을 확인한다. 기술 선택, 환경 변수 이름, 데이터·권한 구조와 마이그레이션을 준비한다. 외부 계정과 배포는 허용 범위 안에서만 진행한다.
2. **공개 화면과 계정**: 소개·랭킹·팀·선수의 승인 디자인, 6자리 인증·프로필·동의·역할별 메뉴를 구현한다. 인증·로그인·접근 제한을 실제 백엔드에 연결한다.
3. **팀 운영**: 승인 신청, 이미지·모집·가입 요청, 정원·단일 소속, 영입·방출·즉시 본인 탈퇴, 대표 교체 승인과 팀 유예를 구현한다.
4. **경기 준비**: 같은 경기 ID의 양 팀 자체 명단, 심판 동시 요청·이메일·첫 수락 확정과 공식 등록 보류를 구현한다.
5. **결과와 순위**: 팀별 제출·비교·버전 재확인, 심판·운영진 승인·이의, 설정된 Elo·기록 집계와 실시간 갱신을 연결한다.
6. **검증과 인계**: 아래 시나리오를 검증하고 실행·배포·운영 인계 문서를 작성한다. 대회 자동화는 세칙 확정 후 진행한다.

테스트는 중요한 권한·경쟁·상태 전이와 계산에 집중한다. 페이지 문구와 단순 레이아웃을 그대로 복제하는 불필요한 테스트를 늘리지 않는다. 합성 데이터를 사용하고 실제 발송·운영 데이터를 테스트에 섞지 않는다.

인계물에는 실행 명령, 선택한 버전, 환경 변수의 이름·용도, DB 마이그레이션·권한, 최초 운영진 설정, 메일·이미지·공개 구독 구성, 배포와 복구 방법, 통과한 검증·제한·미정 사항을 포함한다. 사용자에게 확인된 실제 배포 주소와 연결된 기능을 명확히 보고한다.
