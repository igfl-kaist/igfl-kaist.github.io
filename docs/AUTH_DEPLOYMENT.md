# 인증 1차 구현과 배포

## 현재 범위

- 소개 홈, 로그인/등록 공통 이메일 코드 UI, 인증 완료 후 선수·팀·경기·심판·운영진 화면. 리그 상세는 [운영 인계](LEAGUE_OPERATIONS.md)를 따른다.
- Apps Script의 도메인 검사·6자리·5분·서버 세션·로그아웃.
- 로그인과 등록 목적을 challenge에 묶으며 선수 프로필 등록은 아직 열지 않는다.
- `config.json`에는 배포된 인증 파일럿 `/exec` URL을 연결했다. 빈 endpoint에서는 발송을 막고 준비 중 안내를 표시한다.
- 테스트 이메일은 Script Properties에만 둔다. 소스·커밋·워크플로에 실제 이메일이나 비밀키를 넣지 않는다.

## 서버 배포 준비

1. 현재는 `node scripts/build-gas.mjs`로 만든 `.local/AppsScript.gs`를 Apps Script의 `Code.gs`에 넣는다. 이 번들은 인증·리그·어댑터·소유자 초기화 함수를 포함한다. 매니페스트는 `apps-script/appsscript.json`을 따른다.
2. 서버 비밀값은 최초 초기화에서 생성한다. `Utilities.getUuid()`를 세 번 호출하고 SHA-256으로 64자리 hex 키를 만들어 Script Properties의 `AUTH_SECRET`에 보관한다. Google은 이 API가 `java.util.UUID.randomUUID()`와 동등하다고 명시하고, Oracle은 해당 메서드가 암호학적으로 강한 난수 생성기를 사용한다고 명시한다. UUID v4의 122비트 난수 부분 세 개를 입력하며 중복·형식 이상이면 초기화를 중단한다. 기존 키는 덮어쓰지 않는다. 키를 채팅·콘솔·저장소에 출력하지 않는다. 수동 키 변경은 기존 OTP·세션을 무효화한다. [Google Utilities](https://developers.google.com/apps-script/reference/utilities/utilities#getUuid()), [Java UUID](https://docs.oracle.com/javase/8/docs/api/java/util/UUID.html#randomUUID--).
3. 기본 `AUTH_EMAIL_SCOPE=pilot`에서는 `PILOT_EMAILS`에 허가받은 테스트 주소만 쉼표로 넣는다. 이 목록이 없으면 실패한다. 명시적으로 승인한 경우에만 `AUTH_EMAIL_SCOPE=kaist`로 정확한 `@kaist.ac.kr` 이메일 전체를 허용한다. 알 수 없는 범위는 실패하며, 하위 도메인은 어느 모드에서도 허용하지 않는다. 인증 확대와 선수 정보 등록 개통은 별개다.
4. 소유자가 편집기에서 `initializeAuth`를 한 번 실행한다. 내부의 `initializeAuth_`를 호출하는 편집기용 진입점이다. 밑줄로 끝나는 함수는 편집기 목록에 나오지 않는다. 비공개 인증 시트를 만들고 `AUTH_SHEET_ID`에 연결한다. 기존 저장소가 있으면 재초기화를 거부한다. 웹 API 라우터는 이 함수를 노출하지 않는다. HTML Service나 Apps Script API 실행 배포를 추가할 때 이 소유자용 파일을 배포본에서 제외한다.
5. 필요한 OAuth 범위는 Sheets와 `script.send_mail` 두 가지다. Gmail 받은편지함 읽기·Drive 전체 읽기를 요구하지 않는다. Sheets 범위는 이 파일 하나로 제한되는 권한이 아니므로 소유자의 Google 승인 화면 확인이 필요하다.
6. 웹 앱을 소유자 권한 실행·익명 접근으로 배포한다. 학교 정책에서 익명 접근이 불가능하면 그 상태를 기록하고 별도 호스트 구성을 검토한다.
7. `/macros/s/.../exec` URL을 `config.json`의 `authEndpoint`에 넣는다. URL 자체는 비밀값이 아니다. `/dev` 주소나 리디렉션된 일회성 URL은 저장하지 않는다.

프로젝트: [IGFL Auth Pilot](https://script.google.com/home/projects/1dx9LuoPiC8HdbP-idMXLx1DWr1lqdJge4CcgLBDNCeilVjkRMmrlfyxI/edit). 이는 편집기 링크이며 인증 API URL은 `config.json`을 따른다. 최초 버전 1의 소유자 실행·모든 사용자 호출 설정과 같은 URL을 유지한 채 2026-10-16 **배포 버전 4 / 인증 코드 0.2.0**으로 갱신했다. 사용자 승인으로 `AUTH_EMAIL_SCOPE=kaist`를 적용했다. 실제 선수 가입·시즌·리그 알림은 계속 닫혀 있다. JSON 프로토콜 식별자 `igfl-auth-v1`은 유지한다.

## 구현한 보안 기본값

인증번호는 위 방식으로 생성한 서버 키와 고유 nonce·카운터를 HMAC-SHA256에 넣어 발급한다. 숫자 변환은 rejection sampling을 쓴다. OTP 검증값과 세션 검증값도 서로 다른 용도로 HMAC 처리하고 원문은 시트에 저장하지 않는다. 모든 소비·발급 제한·세션 폐기는 ScriptLock 안에서 처리한다. 메일 발송은 잠금 밖에서 처리하고 발송 실패·중간 실패는 로그인 성공으로 인정하지 않는다.

현재 기본값: 재발송 간격 60초, challenge별 오입력 5회, 이메일별 시간당 5회, 전체 24시간 발송 예약 50회, 세션 12시간. 숫자 6자리·5분을 제외한 값은 운영 전 조정 가능한 기술 기본값이다. 발송 실패도 발송 예산에 포함해 장애 시 재시도 폭주를 막는다. MailApp 잔여 할당량도 확인한다.

브라우저는 같은 탭의 `sessionStorage`에 세션을 보관하고 모든 보호 요청에 서버 확인을 받는다. HttpOnly 쿠키는 아니며 XSS 방어가 필요하다. 외부 스크립트·외부 폰트 없이 CSP를 적용하며 서버 메시지·이메일은 textContent로 렌더링한다. 탭을 닫으면 클라이언트 세션은 사라지고 서버에서도 12시간 후 무효다. 세션 scope은 `auth-pilot`이며 이 값만으로 팀·운영진 권한이 생기지 않는다. 리그 API는 검증된 세션의 내부 ID로 현재 팀/대표를 조회하고 Script Properties에 지정된 운영진 ID를 확인한다.

인증 시트는 파일럿용이다. 요청 시 정리 외에 2026-10-18 시간 기반 자동 정리를 설치·검증했다. 현재 셀의 정리와 Google 변경 이력 파기는 별개이며 실제 선수 수집은 계속 차단한다. [삭제·자동 정리 실제 검증](PRIVACY_VERIFICATION.md).

## 프런트엔드 배포

`node scripts/build.mjs`가 `dist/`에 index·src·config·.nojekyll만 복사한다. Apps Script 코드, 개발 검증 계정, 테스트, 기획, 실제 개인정보, `.local/`은 사이트에 배포하지 않는다. GitHub Actions는 테스트·빌드를 실행한다. 2026-10-16 사용자 승인으로 저장소를 공개하고 Pages Source를 GitHub Actions로 설정했으며 저장소 변수 `PAGES_ENABLED=true`를 지정했다. main 병합/푸시 또는 수동 실행으로 `https://noeyusiohc.github.io/igfl/`에 배포한다. 이전의 지원 플랜 대기 결정은 최신 지시로 대체됐다. 실제 가입·시즌은 서버에서 계속 닫아둔다.

비공개 소스여도 Pages 사이트가 자동으로 비공개가 되는 것은 아니다. 무료 대체 호스팅을 선택한다면 공개 화면과 세션 화면의 권한 범위를 동일하게 검증한다.

## 검증 기록

2026-10-16 로컬 Node 테스트 12개 통과: 서버 키 최초 생성·재초기화 차단·이상 난수 소스 거부, 정확한 도메인/파일럿 제한, 코드 재사용 차단, 5분 만료, 이메일·목적 귀속, 오입력 한도, 재발급 무효화, 메일 실패/할당량, 세션 만료/폐기, 시간별·일별 제한, CORS 클라이언트 전송과 오류 처리.

로컬 브라우저에서 소개 홈·메뉴·로그인·미연결 상태 안내를 확인했다. 390×844 모바일 화면에서 메뉴와 입력 폼이 한 열로 배치되는 것을 확인했다. Google 편집기에 Code.gs와 OwnerSetup.gs를 하나의 Code.gs로 합쳐 저장하고 권한 매니페스트를 반영했다. 사용자의 명시적 승인 후 Sheets 및 메일 발송 OAuth 권한을 적용했다. 소유자 초기화 함수가 Google에서 실제 성공하여 전용 시트·키를 생성했다. 소유자 실행·모든 사용자 호출 설정도 별도 승인 후 배포했다.

Google에 로그인하지 않은 별도 브라우저의 `http://127.0.0.1:4173` 화면에서 `health` 단순 POST를 실행했다. 리디렉션과 CORS를 거친 JSON 응답을 읽어 `서버 응답 확인 완료 · IGFL Auth · 0.1.0`을 표시했다. 같은 화면에서 허가받은 테스트 주소로 실제 발송을 요청해 성공 응답과 5분 입력 화면을 확인했다. 사용자가 수신 코드를 전달해 실제 수신을 확인했다. 코드 한 자리를 바꿔 제출했을 때 서버가 거부했고, 올바른 코드로 검증·세션 조회에 성공해 ‘내 선수 활동’ 화면에 진입했다. 새로고침 후에도 서버에서 세션을 다시 확인해 인증 화면을 유지했다. 로그아웃 API 성공 후 홈으로 돌아왔고, 보호 화면 주소에 재접속하면 로그인으로 이동했다. 테스트 메일은 1회 발송했다. 이 로컬 출처의 성공을 GitHub Pages 출처의 검증 완료로 바꾸어 표현하지 않는다.

생성된 인증 시트의 Drive 권한 메타데이터를 확인했다. `shared=false`이며 권한 항목은 소유자 1명뿐이다. 시트 내용이나 서버 비밀값을 공개 화면·저장소에 복사하지 않았다.

자동 테스트 12개는 Google 서비스 모형을 사용한다. 위의 실제 브라우저 검증과 구분한다. 실제 검증은 Google 권한·시트 쓰기·MailApp 발송·로컬 출처 CORS·정상 인증·오입력·새로고침·로그아웃 경로를 확인했다. 동시 실행·5분 경과·재발급 무효화·기존 토큰 재사용 거부의 실제 서버 시험까지 모두 끝났다는 뜻은 아니다.

남은 실제 검증:

- Pages 출처의 실제 OTP 발송·수신·검증·세션·로그아웃 시험. 공개 JSON 조회/health의 CORS 성공과 구분한다.
- 실제 서버에서 만료·재발급·두 번 검증·동시 검증·로그아웃 전 토큰 재사용 거부 추가 점검.
- 모바일 입력·다시 받기·연결 실패 복구.

실제 검증이 완료되기 전 이 인증을 안전한 운영 서비스로 표현하거나 리그 개인정보를 받지 않는다.

## 리그 기능 추가 검증

2026-10-16 기존 비공개 인증 시트에 리그 전용 탭을 소유자 초기화 함수로 추가했다. 기존 인증 정보와 공유 범위는 유지했다. 버전 3은 36개 자동 테스트를 통과한 공통 리그 엔진·이미지 검증·스냅샷 저장·메일 작업을 포함한다. 로컬 브라우저에서 배포된 리그 API의 공개 응답을 읽어 선수/팀 0과 시즌 준비 상태를 확인했다.

선수 등록·팀 운영·양 팀 결과 확인·심판 최종 승인·랭킹 반영은 별도 localhost 합성 데이터 서버에서 검증했다. 실제 프로필 수집이나 리그 알림 발송을 하지 않았으며, 최초 운영진·수신자·메일 트리거는 아직 설정하지 않았다. 인증 12개 테스트에 리그/저장소 테스트가 추가된 것으로 실제 Google 시험 범위가 자동으로 확대되는 것은 아니다. [구현·운영 인계](LEAGUE_OPERATIONS.md)의 남은 과제를 따른다.


## 공개 GitHub Pages 배포 확인

2026-10-16 사용자 승인으로 `noeyusiohc/igfl`을 공개 전환했다. Pages Source는 GitHub Actions, 저장소 변수 `PAGES_ENABLED=true`, HTTPS 강제 적용이다. PR #1을 main에 병합한 커밋 `6b28a4371615dc782584de2bef0b33926cde8e90`의 [배포 실행](https://github.com/noeyusiohc/igfl/actions/runs/38854152477)에서 테스트·빌드·정적 artifact 업로드·Pages 배포가 모두 성공했다.

[공개 홈페이지](https://noeyusiohc.github.io/igfl/)에서 소개 홈을 확인하고, 랭킹보드가 실제 Apps Script의 빈 리그와 시즌 준비 상태를 읽는 것을 확인했다. 같은 Pages 브라우저의 로그인 화면에서 연결 점검을 실행해 `서버 응답 확인 완료 · IGFL Auth · 0.1.0`을 확인했다. 이로써 Pages 출처의 단순 POST·리디렉션·JSON 응답 읽기/CORS 경로를 확인했다. 이번 배포에서는 인증 메일 발송이나 선수 개인정보 등록을 하지 않았다. 실제 OTP 로그인 전체 흐름의 Pages 출처 검증은 별도로 남긴다.

배포 전후 실제 리그 API 설정을 읽어 `registrationOpen=false`, `seasonOpen=false`, 선수/팀 0을 확인했다. 실제 선수 가입은 계속 닫혀 있다. 홈페이지 공개로 비공개 인증 시트나 Script Properties를 공유하지 않았다. 개발 검증 계정·합성 데이터·로컬 파일도 Pages에 배포하지 않는다.

개인 홈페이지의 기본 경로는 `https://noeyusiohc.github.io/`, IGFL 프로젝트 경로는 `https://noeyusiohc.github.io/igfl/`이다. 이번 설정은 `igfl` 저장소에만 적용했으며 개인 홈페이지 저장소·도메인 설정은 변경하지 않았다.

## KAIST 인증 확대와 Google 메일 잔여량 확인
