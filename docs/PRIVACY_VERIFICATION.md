# IGFL 개인정보 삭제와 자동 정리 검증

기준일: 2026-10-18. **실제 선수 가입·시즌·리그 알림 메일은 닫혀 있다.** 자동 정리 검증 통과와 Google 변경 이력의 완전 파기는 별개의 조건이다. 현재 Sheets 저장 구조는 회원별 변경 이력 파기를 충족하지 못하므로 실제 수집 개통을 승인하지 않는다.

## Google 변경 이력과 백업

소유자 계정의 IGFL 파일 검색과 파일 메타데이터를 확인했다. 기존 인증 저장소는 공유되지 않은 Google Sheets 파일이며 변경 이력이 존재한다. IGFL 이름의 기존 백업은 검색되지 않았다. 이름이 다른 사본·개인 다운로드·학교 관리자의 보관·Google 내부 백업까지 없다는 뜻은 아니다. 실제 개인정보가 있는 이전 버전의 내용을 불필요하게 내려받지 않았다.

Google Drive API는 Google Sheets·Docs의 개별 변경 이력을 삭제할 수 없다. 현재 셀의 `clearContent()`·행 삭제·이전 앱 스냅샷 정리는 변경 이력 삭제 수단이 아니다. API가 반환한 revision 목록은 UI의 전체 이력보다 적을 수 있다. [Google 공식 변경 이력 문서](https://developers.google.com/workspace/drive/api/guides/manage-revisions).

따라서 저장 시트를 새 파일로 교체하는 것만으로도 충분하지 않다. 이전 파일과 모든 사본을 함께 폐기해야 하며, 앞으로 다른 회원이 탈퇴할 때마다 같은 문제가 반복된다. 기존 운영 파일을 이번 시험에서 임의로 영구 삭제하거나 새 파일로 바꿔 인증 서비스를 중단하지 않았다. 개인정보를 평문으로 누적하는 현재 Sheets 어댑터는 파일럿으로 제한한다.

Workspace 관리자는 휴지통을 비운 뒤에도 25일 내 Drive 자료를 복구할 수 있고 Vault 보관 규칙·hold가 적용되면 더 오래 보존될 수 있다. 해당 학교 계정의 Vault 적용 여부·외부 백업·관리자 복구 권한은 리그 계정의 Drive 조회만으로 검증할 수 없다. Drive에서 파일을 영구 삭제한 사실과 Google 전체 시스템의 즉시 물리적 파기를 동일하게 안내하지 않는다. [Google 관리자 복구 문서](https://knowledge.workspace.google.com/admin/drive/recover-deleted-files-and-folders-for-drive-users?hl=en).

## 자동 정리 구현

`runScheduledPrivacyMaintenance()`가 트래픽과 무관하게 실제 운영 저장소의 `runPrivacyMaintenance()`를 실행한다. 준비된 합성 시험은 같은 정리 함수를 별도 비공개 시트·별도 속성 공간으로 한 번 실행한다. 서버 비밀키·운영 스냅샷 포인터·운영진 지정·가입 스위치를 합성 시험에 사용하거나 복사하지 않는다. 메일을 보내지 않는다.

- 만료·철회된 세션 삭제, 만료·소비된 인증번호 해시 제거, 24시간 지난 만료 인증 메타데이터 삭제.
- 등록 회원·운영진을 제외한 24시간 지난 인증 계정 매핑 삭제.
- 90일 지난 운영 로그·홈페이지 알림·경기 제안·메일 작업 정리.
- 확정한 시즌 종료 후 2년이 지난 개인 시즌 기록 정리. 팀 스코어·Elo는 보존한다. 실제 시즌 날짜가 미정이면 임의의 종료일을 정하지 않는다.
- 미완료 회원 탈퇴 재시도 후 인증 계정·세션과 현재 셀에 있는 과거 앱 스냅샷 정리.

`PRIVACY_MAINTENANCE_STATUS`에 실행 횟수·시작/종료·마지막 성공 시각·고정 실패 코드·삭제 건수만 기록한다. 이메일·이름·인증번호·세션 토큰·공급자 예외 메시지를 기록하지 않는다. 작업이 중단되면 `running`, 오류가 나면 `failed`가 남고 다음 실행에서 재시도한다. 성공 시각이 2시간 이상 갱신되지 않거나 실패가 반복되면 운영자가 Apps Script 실행 화면을 확인한다. 상태 자동 외부 감시 메일은 아직 연결하지 않았다.

인증 코드·세션은 만료 즉시 서버 검증에서 거부한다. 현재 셀의 물리적 정리는 시간 트리거 실행 시점에 일어나므로 정상 시간별 실행에서는 설정 기간에 최대 약 한 시간 지연이 더해질 수 있다. Google 트리거 장애 시 상한을 보장할 수 없다. ‘현재 셀 최대 24시간’처럼 오차 없이 파기한다고 안내하지 않는다. Google 자체 변경 이력 잔존은 이 시간과 별개다.

## 개통 차단

실제 Apps Script의 선수 가입은 `LEAGUE_REGISTRATION_OPEN=true`와 별도 `PRIVACY_STORAGE_APPROVED=true`가 모두 있어야 열린다. 두 번째 속성은 현재 미승인이다. 자동 정리·합성 시험·홈페이지 배포·이전 스냅샷 복원은 이를 승인하지 않는다. 시즌과 리그 알림 메일 스위치도 독립적으로 닫혀 있다.

현재 파일럿에서 전체 인증 시트 또는 Script Properties 백업을 만들거나 운영으로 복원하지 않는다. 원시 사본에는 탈퇴 전 프로필·인증 계정·토큰 해시가 남아 사용자를 되살릴 수 있다. 복원 시 운영 설정을 덮어쓰지 않고, 백업 외부에 유지하는 삭제 원장 적용·모든 이전 인증 폐기·권한/결과 재검증을 갖춘 복구 절차가 필요하다. 이 원장과 안전한 운영 복원은 아직 구현하지 않았다. 부분 쓰기 실패의 이전 포인터 보호는 백업 복원 허가를 뜻하지 않는다.

실제 모집 전에는 회원별 파기와 백업 복구 방지를 지원하는 저장소로 개인정보·인증 정보를 옮기는 안을 우선 검토한다. Apps Script 메일 발송과 정적 GitHub Pages 프런트엔드는 유지할 수 있다. 새 유료 서비스나 계정은 이번 작업에서 만들지 않았다. 처리방침의 Google 수탁·국외 이전 세부 고지도 계속 미완료다.

## 검증 증거

로컬 자동 테스트 60개가 통과했다. 새 검증은 공통 코드 전체를 실행해 별도 시험 저장소 격리, 탈퇴 재시도, 실패 로그의 비밀 미노출, 마지막 성공 시각 유지, 유효 계정·팀 기록 보존, 원래 가입 스위치만으로 개인정보 검토를 우회할 수 없음을 확인한다. 실제 Google 실행 결과와 사본 정리 결과는 아래에 기록한다.

2026-10-18 15:40:11 KST Apps Script 실행 목록의 `Head / runScheduledPrivacyMaintenance / 시간 기반` 실행을 확인했다. 15:40:26 KST 별도 합성 시트 시험이 `passed`로 끝났고 11개 검증이 모두 참이었다. 시험용 1분 트리거를 단일 1시간 주기로 변경하고 편집 화면을 다시 열어 `1시간마다` 저장값과 오류율 0%를 확인했다. 15:41:28 소유자 진단에서 운영 정리 `succeeded`, 누적 2회 실행·마지막 성공 시각, 합성 시험 결과를 다시 확인했다. 시험 시트에는 웹 API 요청을 보내지 않았다. 공개 홈페이지의 별도 조회가 존재했으므로 운영 파일 전체가 무트래픽이었다고 주장하지 않는다.

합성 시험 통과 항목은 만료 인증/세션 삭제, 만료 코드 해시 제거, 유효 인증/세션 보존, 미등록 계정 삭제, 등록 회원/운영진 보존, 탈퇴 작업 완료, 이전 앱 스냅샷 셀 비우기, 오래된 감사 로그 삭제, 만료 시즌 개인 기록 삭제, 팀 스코어 보존, 가입/시즌 닫힘 유지다.

실제 Drive 사본 시험에서는 정리 전 복사한 비공개 백업의 탈퇴 대상 합성 계정이 원본 정리 후에도 남아 있음을 확인했다. 사본 복원 시 삭제한 정보가 재등장할 수 있다는 근거다. 시험 원본과 백업 사본 모두 Drive 영구 삭제 요청 성공 뒤 파일 메타데이터 조회가 `404 / NOT_FOUND`인 것을 확인했다. 운영 원본 파일은 유지했다. 이 결과는 현재 계정의 Drive 접근에서 제거된 증거이며 Workspace 관리자 복구·Vault·공급자 내부 백업 파기의 증명은 아니다.

## 재현과 운영 점검

1. `node --test`, `node scripts/build-gas.mjs`, `node scripts/build.mjs`를 실행한다.
2. 기존 Apps Script 프로젝트에 번들을 저장한다. 기존 Sheets·메일 두 OAuth 범위만 유지하며 Drive 삭제나 ScriptApp 관리 범위를 추가하지 않는다.
3. 소유자가 `preparePrivacyProbe()`를 한 번 실행한다. 이름과 이메일은 모두 합성이며 실사용 저장소와 별도의 새 비공개 파일이다. 중복 실행은 거부한다.
4. Apps Script 트리거 UI에서 `runScheduledPrivacyMaintenance` / `Head` / 시간 기반을 지정한다. 짧은 시험 주기로 자동 실행을 확인한 뒤 한 시간 주기의 단일 트리거로 유지한다. 이 함수의 공개 API 호출 경로는 없다.
5. `inspectPrivacyMaintenance()`의 운영 `succeeded`, 마지막 성공 시각과 합성 `passed`·11개 항목을 확인한다. 실행 목록의 시간 기반 유형과 대조한다. 직접 실행만으로 무접속 자동 실행을 통과 처리하지 않는다.
6. 합성 사본에 남은 탈퇴 전 표식을 확인한 뒤 시험 원본과 사본을 삭제한다. 운영 원본은 이 절차의 삭제 대상이 아니다. 재시험 시 삭제 완료한 합성 `PRIVACY_PROBE` 속성만 지운 뒤 새 fixture를 만든다. 실제 비밀키나 운영 속성을 초기화하지 않는다.
